# WRITE Settlement Manager V10.0 生产验收报告

结论：**PASS，可以生成生产部署包**。本结论覆盖本地完整工作流与静态部署文件；GitHub 推送和 Cloudflare 发布未在本次构建中执行，由包内一键部署器执行并在线复核。

## 人工发票学习基准

- 原始发票文件 60 份，去重后 55 份；只纳入 52 份已完成 FACT，忽略 3 份明确未完成版本。
- 纳入 1,806 个有效人工统计行，覆盖 269 种人工 Description。
- 固化习惯：同国按完整包裹组合统计；Description 使用短会计名；尺寸 `×` 不当数量；赠品需明确免费证据；固定模板与银行信息不改。

## 生产规则验收

- 全部国家在一张 FACT；中国仓/法国仓不拆票，同国同组合跨仓合并。
- 一个正常订单/运单算一个包裹，多商品仍为一个包裹；赠品专单不计。
- 精确重复订单+运单+内容去重；同订单多运单分别计包裹并标红；其他冲突记录保留并标红。
- 未知商品继续出发票：FACT 使用保守缩写并标红，原始名称、SKU 和来源留在 audit JSON。
- 成本、运费、单价、金额和总金额一律留空标红，无备注；Excel、PDF、audit JSON 全自动生成。

## 多行业真实格式端到端

- 输入：按历史人工订单表真实列结构生成的 3 个订单 Sheet，3,020 条记录。
- 行业：文具、个护、家居、服饰、电子配件、户外、汽车用品、宠物、厨具、未知新品，共 10 类。
- 变量：8 个国家、4 类仓/店铺、单/多商品、尺寸 `×`、空价、零价、文本价、负价、赠品、重复、同订单多运单、长文本、未知 SKU。
- 结果：3,020 条全部导入，精确去重 9 条，识别 11 个多运单订单，生成 523 个 FACT 组合行，`missingSourceItems=0`，Excel/PDF/audit JSON 均成功。
